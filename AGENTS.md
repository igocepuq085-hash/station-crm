# AGENTS.md

## Назначение проекта

`station-crm` - это MVP CRM для начальника службы погрузки и маневровых работ. Сервис должен помогать быстро понять, как прошла работа станции за сутки, какие грузы и вагоны были обработаны, что оформлено и что отправлено.

## Главная технологическая цепочка

Основная цепочка управления и аналитики:

```text
Сургут -> прибыло на Промышленную -> обработано на Промышленной -> погружено -> оформлено -> отправлено в Сургут
```

## Правила предметной области

1. Нельзя считать просто общий парк вагонов. Всегда нужно учитывать соответствие продукта и вагонов под продукт.
2. Ключевая логика будущих расчетов: продукт на ЗСК + подходящие вагоны под продукт + годность вагонов + оформление + отправление.
3. Вагоны под СУГ не равны автоматически вагонам под конкретный продукт.
4. Нужно различать продукты: ПБТ, ПБА, ПТ, ПТ ГОСТ, ПА, ФБ, БТ, ШФЛУ, ПГФ, УВФ и другие.
5. Все парсеры должны быть устойчивыми к изменению структуры Excel: нельзя завязываться только на фиксированные номера строк и колонок без fallback-логики.
6. Сначала сохраняется сырой слой данных: исходные файлы, сырые извлеченные строки, ссылки на источник.
7. Только после сохранения сырого слоя можно нормализовать показатели и строить расчеты.
8. Сырой слой данных удалять нельзя.
9. Все расчеты должны иметь ссылку на источник: файл, лист, строка, ячейка.
10. Дашборд должен быть управленческим: KPI, графики, тренды, день/ночь, месяц, вывод агента.

## Инженерные правила

- Alembic в текущем MVP не подключен.
- SQLite используется как локальная база MVP.
- Таблица `raw_extracted_rows` является базовым сырым слоем для найденных строк.
- При развитии нормализованных таблиц нельзя ломать возможность вернуться к исходной строке и файлу.
- Новые парсеры должны быть терпимыми к пустым строкам, объединенным ячейкам, переименованным листам и изменению порядка колонок.
